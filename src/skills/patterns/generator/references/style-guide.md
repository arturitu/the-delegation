# Style Guide: Technical Documentation

## Tone and Voice
- **Professional & Objective**: Avoid marketing fluff. Use clear, direct language.
- **Active Voice**: "The system executes..." rather than "The system is executed by..."
- **Concise**: If it can be said in 5 words, don't use 10.

## Formatting Rules
- **Headers**: Use H1 for titles, H2 for major sections, H3 for sub-sections.
- **Lists**: Use bullet points for features and numbered lists for sequences.
- **Code Blocks**: Always specify the language for syntax highlighting.
- **Alerts**: Use GitHub-style alerts (> [!NOTE]) for critical info.
